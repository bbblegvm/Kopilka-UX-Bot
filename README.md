# 🐭 Telegram-бот «Копилка»

Бот помогает накопить на мечту: считает, сколько откладывать каждый день, напоминает раз в день,
а за пополнения даёт монеты, на которые можно одевать маскота.

## Запуск

1. Создайте бота у [@BotFather](https://t.me/BotFather) и скопируйте токен.
2. Установите зависимости (Python 3.10+): `pip install -r requirements.txt`
3. Скопируйте `.env.example` в `.env` и впишите `BOT_TOKEN`.
4. Запустите из папки проекта (рядом должна лежать папка `assets/`): `python bot.py`

Данные хранятся в `piggybank.db`, при перезапуске не пропадают.

## Как устроен бот

`/start` → маскот здоровается → «➕ Добавить цель» → название → сумма → срок (кнопки или текстом) →
**главное меню**:

```
[картинка маскота]
🎯 Цель: Ноутбук
📊 Прогресс: 1 250 / 70 000 ₽
📅 Срок: до 24.11.2026
🪙 Монеты: 50

[💰 Пополнить копилку]
[📊 Прогресс] [🛍 Магазин]
```

- После создания цели бот пишет, сколько откладывать в день, чтобы успеть к сроку.
- **Пополнить копилку** — «сколько ты отложил?» с кнопками: сумма по плану на день (нажал — и готово)
  и «✏️ Другая сумма» (или просто напишите число) → сообщение с **радостным** маскотом и новым прогрессом.
  Сумма на кнопке пересчитывается от остатка: если сегодня уже пополняли, план считается с завтрашнего дня.
- «Пока не хочу» в уведомлении → **грустный** маскот и кнопки «Пополнить копилку» / «Прогресс».
  Монеты (по умолчанию 50) даются **за первое пополнение в день**, дальше в этот день пополнять можно, но монет нет.
- **Прогресс** — подробный экран с расписанием по дням (сколько откладывать сегодня/завтра и дальше).
- **Магазин** — бантик 30, шапочка 50, очки 70 монет. Купленное можно надевать снова бесплатно.
- **Сроки**: неделя (тест), 1 месяц, 3 месяца, 6 месяцев, 1 год или свой текст («3 месяца», «10 недель», «90 дней»).
  Кнопку «Неделя (тест)» на время пилота можно убрать в `TERM_CHOICES` в начале `bot.py`.

## Уведомления

Раз в день в `REMIND_TIME` (по `TZ_NAME`) всем, у кого есть активная цель:
- не приходят, если человек уже пополнил копилку сегодня;
- не приходят в день создания цели, если она создана после `REMIND_TIME` (первое придёт завтра);
- отправляются только в окне `[REMIND_TIME; REMIND_TIME + REMIND_WINDOW_MIN)`.

Бот должен быть запущен. Для круглосуточной работы нужен сервер (VPS и т. п.).

### Уведомление не пришло — что проверить
1. **Перезапустите бота после правки `.env`.** Файл читается только при запуске.
2. Отправьте боту **`/notifystatus`** (нужен `ADMIN_IDS`, см. ниже). Бот покажет своё текущее время, настройки
   и прямо напишет причину, если уведомление сегодня не придёт. Частые причины:
   - сегодня уведомление уже приходило (бот шлёт не чаще раза в день): `/nextday` сбросит это;
   - вы сегодня уже пополняли копилку (тогда уведомление не нужно);
   - цель создана позже `REMIND_TIME` (первое придёт завтра);
   - бот был выключен в `REMIND_TIME` и включён после окончания окна;
   - время бота не совпадает с вашим: бот живёт по `TZ_NAME` (по умолчанию Москва), а не по часам компьютера.
3. В консоли, где запущен бот, видны строки «Уведомление … отправлено / пропущено: причина».

### Как тестировать, если бот включён не 24/7
Пример: бот работает с 12:00 до 20:00.
1. В `.env`: `REMIND_TIME=13:00`, `REMIND_WINDOW_MIN=360` (запустили в 12:00 или в 17:00 — уведомление всё равно придёт).
2. Создайте цель **до** 13:00 (после этого времени цель получит первое уведомление только завтра).
3. Дождитесь 13:00. Повторно в тот же день оно не придёт.

Не хотите ждать — используйте тестовые команды ниже.

## Тестовые команды (только для `ADMIN_IDS`)

1. Отправьте боту `/id`, впишите полученное число в `ADMIN_IDS` в `.env`, перезапустите бота.
2. Теперь вам доступны (остальным пользователям эти команды ничего не делают):

| Команда | Что делает |
|---|---|
| `/reset` | стирает ваши данные: бот снова видит вас впервые, можно заново тестировать `/start` и создание цели |
| `/notifystatus` | диагностика: придёт ли вам уведомление сегодня, а если нет — почему |
| `/notify` | сразу присылает оба варианта ежедневного уведомления |
| `/nextday` | «перематывает» на день вперёд: сегодняшние пополнения становятся вчерашними (снова можно получить монеты, снова придёт уведомление) |
| `/givecoins 100` | добавляет себе монеты (чтобы проверить магазин, не ждать несколько дней) |

Новых ботов создавать для этого не нужно. Но если пилот идёт у настоящих пользователей, удобно иметь
второго бота для разработки: у @BotFather другой токен и другой `DB_PATH` в отдельном `.env`.

## Картинки маскота (`assets/`)
| Файл | Откуда |
|---|---|
| `mascot.png`, `mascot_hat.png` | ваши рисунки |
| `mascot_bow.png`, `mascot_glasses.png` | **временные**, дорисованы автоматически поверх вашего маскота |

| `mascot_happy.png`, `mascot_sad.png`, `mascot_hat_happy.png`, `mascot_hat_sad.png`, `mascot_bow_*`, `mascot_glasses_*` | **временные**: та же картинка с подписью happy / sad |

Имя файла настроения: `<файл наряда без .png>_<happy|sad>.png`. Если нужного файла нет, бот покажет обычную картинку.
Временные картинки настроений можно пересоздать командой `python tools/make_mood_placeholders.py` (нужен Pillow).

Чтобы заменить, положите свой файл с тем же именем. Названия, цены и файлы предметов — в словаре `SHOP`
в начале `bot.py`. Текст приветствия — в константе `GREETING`.

## Что пока не реализовано
- Рост маскота вместе с накоплениями (нужны рисунки стадий).
- На маскоте виден один предмет за раз.
